# Phase 4C: mixed-coverage release contract

Status: implemented with fixture data; no production release activated

Policy: `uncertainty-aware-ranking-policy-1.0`

Schema negotiation:

- release and validation schema 3 remain supported and retain complete-matrix semantics;
- release and validation schema 4 add criterion-level coverage metadata and outcomes;
- consumer catalog schema 1 remains paired with release 3;
- consumer catalog schema 2 is paired explicitly with release 4; and
- an old criterion is never inferred to be partial coverage.

The active production pointer remains `2026-07-27.1` on release schema 3. Phase 4C did not ingest
candidate sources, publish a production release, change the API, or change ranking behavior.

## Coverage modes

| Mode | Contract |
| --- | --- |
| `GLOBAL_CORE` | Exactly 91 valid outcomes and 91 scores; no activation threshold. |
| `CONDITIONAL_COMPLETE_CASE` | At least 82 valid outcomes and scores; activation threshold is in `[0, 1]`. |
| `DIAGNOSTIC_ONLY` | May be retained for analysis but is not criterion-ready. |

Every schema-4 criterion has exactly one country outcome for every member of
`stable_supported_v1`. An outcome is one of `valid`, `missing`, `stale`, `invalid`, or `rejected`.
Valid outcomes carry an observation ID and no reason code. Every non-valid outcome carries one or
more normalized reason codes and no observation ID.

Scores must reconcile one-for-one with valid country outcomes. A missing score is valid only when
the corresponding explicit outcome is non-valid; a score for such an outcome is rejected.

## Reconciled metadata

The manifest, validation report, and catalog store identical coverage metadata for each criterion:

- coverage mode, stable universe ID, and denominator;
- valid and minimum-valid counts plus all five outcome counts;
- PCC activation threshold;
- experimental flag;
- source versions and scoring-method version; and
- allowed score range.

The repository rejects any disagreement across those three artifacts, incomplete or duplicate
outcomes, score/outcome mismatch, source or observation lineage mismatch, invalid score range,
unsupported policy version, incomplete global core, or PCC coverage below its configured minimum.
Product readiness also requires the release's configured minimum number of ready global-core
criteria.
